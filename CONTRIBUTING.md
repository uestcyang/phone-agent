# Contributing

Useful contributions include reproducible installation reports, small transport fixes and tested native-executor adapters. Keep model planning and tool execution in the native harness rather than adding a parallel agent loop.

Before opening a pull request, run the applicable server or Flutter tests described in `docs/VALIDATION.md`. A bug fix should include a regression test with synthetic data. State which OS, runtime and executor version you tested and which behavior you did not test.

Do not commit device tokens, administrator tokens, cookies, signing keys, production hostnames, user directories, real messages or private artifact names. Do not attach screenshots from personal sessions. Package names and example identities should remain generic.

Adapter integrations must use the provider's supported authorization and invocation methods. Do not submit cookie extraction, subscription circumvention or silent credential discovery.

Preserve dependency licenses and notices. Changes are subject to the existing project license. Report vulnerabilities without publishing exploit details or credentials in a public issue.
